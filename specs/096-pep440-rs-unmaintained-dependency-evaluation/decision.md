# Decision record: pep440_rs 0.7.3 vs uv-pep440 0.0.99 (issue #1929)

> [!warning] Provisional
> Outcome: **keep `pep440_rs` 0.7.3 for now; replace is conditional** on (i) D1 resolved, (ii) the joint `pep508_rs` swap passing its own PEP 508 differential, (iii) user approval of the new crates containing `unsafe` listed in section 5. Same gate reading as [[095-node-semver-dormant-dependency-evaluation/decision|the 095 record]]: a non-intentional candidate-bug divergence (D1) fails the gate until it is fixed or the user accepts it as an intentional difference, and a new crate with `unsafe` needs user approval. Implementation, if approved, is a follow-up issue, not this PR. Items marked `provisional, needs user review` are policy defaults chosen in the stricter-gate direction; the spec's `[NEEDS CLARIFICATION]` markers are not closed by this record.

## 1. Method

- Snapshot: `git archive a2a20c639` extracted in the session scratchpad; no build from the worktree, nothing under `crates/` changed.
- Corpus (not committed, regenerated by the commands in section 7), compared against the PyPA `packaging` 26.3 oracle as a third column:
  - Synthetic (seed 1, n=40,000): 38,950 unique version strings (curated PEP 440 examples, aliases, epochs, local, pre/dev/post, u64 boundaries, unicode and NUL, plus grammar-generated), 39,998 ordering pairs, 39,978 specifier sets (all operators, `.*`, `===`, `~=`, local, malformed), 239,986 `contains` pairs.
  - Real-world (read-only registry GETs): 10,260 version strings from 120 PyPI projects, 635 distinct specifiers (`requires_dist`, `requires_python`), 149,877 ordering pairs, 94,591 `contains` pairs.
- Two levels:
  - Engine level: bare `pep440_rs` 0.7.3 vs `uv-pep440` 0.0.99 (`Version::from_str`, predicates, `Ord`/`Eq`, `VersionSpecifiers::from_str`, per-specifier and set `contains`, `operator()`, `version()`).
  - Wrapper level (the plan's definition of "current engine"): `PypiFormatter` at the snapshot, built once as-is and once with `pep440_rs = { package = "uv-pep440", version = "=0.0.99" }` in the root `[workspace.dependencies]`: `compile_bounded_requirement` (incl. `matches`, `explicitly_excludes`), `version_satisfies_bounded_requirement`, `requirement_opts_into_prereleases`, `is_bounded_requirement_up_to_date`, `format_version_replacing`, `PypiVersion::is_prerelease`.

### 2.3 Panics

Wrapper-level fuzz (seeds 31-33, 900,000 records per seed over the `PypiFormatter` entry points, 2 MiB stack): both builds complete with exit 0.

## 3. Open questions answered

- **OQ-1 (joint with pep508_rs).** `cargo tree -i pep440_rs` on the snapshot: `pep508_rs 0.9.2` depends on `pep440_rs 0.7.3`. Swapping `pep440_rs` alone compiles but leaves both crates in the tree (`cargo tree -p deps-pypi` shows `pep440_rs` under `pep508_rs` and `uv-pep440` beside it), so the unmaintained crate is not removed. Swapping both (`uv-pep508 0.0.99`): 207 -> 243 unique crate versions with `node-semver` kept, 235 with all three swaps; the `uv-*` closure adds `uv-errors`, `uv-fs`, `uv-macros`, `uv-normalize`, `uv-pep508`, `uv-small-str`, `uv-static`, `uv-version`, `uv-warnings`, `rkyv`, `tempfile`, `rustix`, `textwrap` and others. `uv-pep508` has 12 `unsafe` lines in its `src/`. `uv-pep508 0.0.99` returns a clean `Err` (no panic) on the #703 shapes `0m[1A.]`, `a[1.]`, `a[0A.]`, `x[9m.]`, where `pep508_rs 0.9.2` panics. A PEP 508 differential (parse parity, markers, URL requirements, error redaction) was not run: the decision is joint, but its PEP 508 half is unevaluated.
- **OQ-2 (API difference).** 0 call-site edits (section 2.4).
- **OQ-3 (publishing).** `uv-pep440` and `uv-pep508` carry the same version on the same days (both 0.0.99 on 2026-11-03), i.e. they are released in lock-step with `uv`'s weekly train, not independently. Breaking-change history on the 0.0.x line was not diffed; an exact `=0.0.N` pin in root `[workspace.dependencies]` fits the convention (no features) and will be flagged by `cargo outdated` weekly.
- **OQ-4.** MSRV 1.97, edition 2024, Apache-2.0 OR BSD-2-Clause; transitive licenses pass `cargo deny` (section 2.4).
- **OQ-5 (corpus).** Spec examples and fixtures-style curated cases, grammar generation, and real PyPI versions and `requires_dist` from 120 projects (10,260 versions, 635 specifiers). Lock-file samples were not collected.

## 4. Gate (FR-018, FR-019, FR-020)

Gate reading used here and in the 095 record (stricter direction, provisional): every non-intentional divergence where the candidate is wrong (a "candidate bug") blocks eligibility until fixed upstream, guarded in the wrapper, or accepted by the user as an intentional difference; a divergence where the current engine is wrong does not block.

- FR-001..FR-009: D1 is a candidate bug (u64::MAX segment rejected), so FR-007's "parse every string the current engine parses" is not met strictly. D2 (current bug) and D3 (benign) do not block. MSRV, license, dependency weight pass; no open fuzz panic.
- Outcome: **keep** for now. D1 is practically unreachable (no real version has a segment of 2^64-1; none in 10,260 real versions), so the expected resolution is a user decision to accept it as intentional, after which the gate passes at the PEP 440 level.
- Replace remains the intended direction, conditional on D1, the joint PEP 508 differential and the `unsafe` approval in section 5. "Vendor" is not needed.

## 6. Re-evaluation triggers (FR-021)

- A RUSTSEC advisory against `pep440_rs` or `pep508_rs`.
- An MSRV or edition incompatibility of `pep440_rs` with a workspace bump.
- A PEP 440 correctness bug in `pep440_rs` reproduced live (D2 is already one; it does not change user-visible results on real data).
- `uv-pep440` reaching 0.1 or 1.0, or `uv-pep508` failing the PEP 508 differential.
