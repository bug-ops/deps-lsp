1//! `.github/workflows/*.yml`/`*.yaml` parser using `yaml-rust2`'s event-driven
2//! (`MarkedEventReceiver`) API.
3//!
4//! An event-driven parser, rather than a tree-and-text-search approach (`deps-dart`'s), is
5//! what makes duplicate `uses:` lines addressable with distinct ranges — the common case in
6//! real workflows (the same action pinned at the same or different refs across several
7//! jobs).
8//!
9//! # Reusable-workflow calls
10//!
11//! `owner/repo/.github/workflows/x.yml@ref` is parsed, its `owner/repo` truncated for
12//! display, and recognized — but deliberately treated as **non-resolvable**, the same shape
13//! as `./local`/`docker://`. The complexity here is semantic, not syntactic: such a call is
14//! versioned by the *host repository's* tags, which for a reusable-workflow host are
15//! routinely its unrelated package releases rather than that specific workflow's — "outdated
16//! → update to vX" would then rewrite the pin to a tag that may not even contain the
17//! workflow. A wrong diagnostic on a supply-chain feature is worse than none. Subdirectory
18//! actions (`github/codeql-action/init@v3`) are unaffected: their repo's tags genuinely are
19//! the correct versioning, so they stay fully resolvable. The discriminator is whether the
20//! path segments after `owner/repo` start with `.github/workflows/`.

39/// Upper bound, in bytes past a ref's end, on how far [`ref_is_last_token_on_line`] and
40/// [`extract_comment_tag`] look ahead on the ref's physical line (issue #885 rework).
41///
42/// Deliberately a separate constant from `deps_core::lsp_helpers::MAX_FALLBACK_SCAN_BYTES`
43/// (code-review finding #4 on the original #885 fix): that constant bounds a byte-offset
44/// *correction* fallback with a completely different cost/correctness profile (a handful of
45/// bytes in real manifests) — reusing it here coupled two unrelated tuning knobs, so that
46/// crate's own consumers (including `deps-gitlab-ci`) would have silently inherited any
47/// widening made for this file's rest-of-line comment/continuation lookahead.
48///
49/// Sized so realistic GitHub Actions inline comments/tags are essentially never truncated:
50/// even a verbose annotation (`# pinned to v4.2.100, see PR #1234 for CVE-XXXX-XXXX`) is
51/// well under a few hundred bytes, leaving an order of magnitude of headroom. Worst-case
52/// cost is still bounded rather than reintroduced as O(document length): with
53/// `deps_core::MAX_DEPENDENCIES_PER_DOCUMENT` (5000) ref-pinned dependencies packed onto
54/// one adversarial physical line, each separated by a whitespace-only gap this large, the
55/// two lookahead scans together visit at most `5000 * 2 * 4096` ≈ 40 MB total (each of the
56/// ~20 MB of distinct gap content visited by both scans) — the distinct content alone is
57/// already most of `deps_core::parser::MAX_YAML_EXPANDED_BYTES`'s 32 MiB document-size
58/// ceiling, so this is close to the worst case such a document can express, not an
59/// understatement of it. `test_build_dependency_rest_of_line_lookup_is_not_quadratic` below
60/// demonstrates this stays a small, constant-per-call cost independent of how much content
61/// follows on the line, unlike the unbounded `find('\n')` scan this issue was filed
62/// against.
63const REST_OF_LINE_WINDOW_BYTES: usize = 4096;

65/// Whether [`build_dependency`]'s bounded rest-of-line window ([`REST_OF_LINE_WINDOW_BYTES`])
66/// covers the ref's entire physical line, or was cut short before reaching the real
67/// end-of-line content.
68///
69/// A plain `bool` here previously required the single call site to pass `!window_truncated`
70/// — a negation that a future edit could silently drop or invert, flipping a
71/// security-relevant conservative default to a permissive one with no type-level signal
72/// (code-review finding #7). The two variants make the call site's intent explicit instead.
73#[derive(Clone, Copy, PartialEq, Eq)]
74enum WindowCoverage {
75    /// The window reached the line's real end — nothing on the line is unexamined.
76    FullLine,
77    /// The window was cut short by [`REST_OF_LINE_WINDOW_BYTES`]; real content may exist
78    /// just past it that this scan never saw.
79    Truncated,
80}

82/// Whether nothing unsafe to overwrite follows the ref on its source line: only
83/// whitespace, or a whitespace-preceded YAML comment (the same comment-start rule
84/// [`extract_comment_tag`] uses), all the way to end of line.
85///
86/// Security audit finding (pre-existing in the #473 quickfix, now shared by the bulk
87/// pin-all-to-SHA aggregator, issue #633): a SHA-pin edit appends `# <tag>` right after
88/// the ref, turning everything after it into a YAML comment. For a `uses:` step written
89/// in **block** style that is safe — nothing meaningful follows on the line. For a step
90/// written in YAML **flow** style (`{uses: actions/checkout@v4, with: {node: 20}}`), real
91/// YAML content (`, with: {...}}`) follows the ref on the same line, and commenting it out
92/// produces invalid YAML (an unterminated flow mapping) — silently breaking the workflow
93/// rather than merely leaving it unpinned. This function has no notion of flow vs. block
94/// context itself; it just checks "would writing a comment here swallow real content",
95/// which is true in exactly the flow-style case and false for ordinary block-style lines.
96///
97/// `rest_of_line` may be a window bounded well short of the line's real end (issue #885
98/// rework); `window` being [`WindowCoverage::FullLine`] is the answer to use only when the
99/// *entire* window is whitespace with no `#`/real content found in it — a case this
100/// function cannot resolve on its own, since real content might still exist just past a
101/// truncated window. Finding a `#` comment or non-whitespace content within the window is
102/// always a definitive answer regardless of `window` (impl-critic finding: gating a found
103/// `#`/non-whitespace answer on "was the window truncated" discarded information the
104/// window already proved, producing a false negative that withheld the SHA-pin quickfix on
105/// a perfectly safe line whose comment tag resolved fine within the window).
106// `bytes[i - 1]` is guarded by the `i > 0` conjunct immediately before it.
107#[allow(clippy::indexing_slicing)]
108fn ref_is_last_token_on_line(rest_of_line: &str, window: WindowCoverage) -> bool {
109    let bytes = rest_of_line.as_bytes();
110    for (i, &b) in bytes.iter().enumerate() {
111        if b == b'#' && i > 0 && bytes[i - 1].is_ascii_whitespace() {
112            return true;
113        }
114        if !b.is_ascii_whitespace() {
115            return false;
116        }
117    }
118    window == WindowCoverage::FullLine
119}

121/// The first whitespace-delimited token after a whitespace-preceded `#` in
122/// `rest_of_line` (the raw source text following a ref's end, up to end of line),
123/// accepted as a comment tag only when it has the shape of a full `major.minor.patch`
124/// version ([`is_full_semver_shape`], shared with the crate's `BareRequirementPolicy`
125/// gate so the two mechanisms can't diverge — B2/B3/N1).
126///
127/// Returns `(tag_text, byte_offset_in_rest_of_line_where_the_token_ends)`. A `#` not
128/// preceded by whitespace is not a YAML comment and is skipped (only the *first*
129/// whitespace-preceded `#` is considered); a shape-rejected token (`# v4`, `# v4.2`) or
130/// no `#` at all yields `None` — the ref degrades to a bare, commentless pin.
131///
132/// `window` reflects whether `rest_of_line` was cut short of the line's real end (issue
133/// #885 rework). When the token runs all the way to the end of `rest_of_line` with no
134/// terminating whitespace found *and* the window was [`WindowCoverage::Truncated`], the
135/// token's true extent is unknown — real digits may continue just past the window edge
136/// (e.g. a window boundary landing mid-digit turns `v4.2.100` into `v4.2.10`, which still
137/// passes [`is_full_semver_shape`] and would otherwise be silently recorded as the real
138/// version — code-review finding #1). Such an ambiguous token is rejected as `None` rather
139/// than risking a truncated-but-plausible-looking version; a token that ends before the
140/// window's edge (a terminating whitespace was actually observed) is unaffected regardless
141/// of `window`, since its boundary was genuinely seen.
142// `i` is a byte index holding ASCII `b'#'`; `token_len` from `find(char::is_whitespace)` or
143// `.len()`. Both slice bounds are always char boundaries. `bytes[i - 1]` is short-circuited
144// by the `i == 0 ||` conjunct, and `i` ranges `0..bytes.len()` from the loop.
145#[allow(clippy::string_slice, clippy::indexing_slicing)]
146fn extract_comment_tag(rest_of_line: &str, window: WindowCoverage) -> Option<(&str, usize)> {
147    let bytes = rest_of_line.as_bytes();
148    for i in 0..bytes.len() {
149        if bytes[i] != b'#' {
150            continue;
151        }
152        if i == 0 || !bytes[i - 1].is_ascii_whitespace() {
153            continue;
154        }
155        let after_hash = &rest_of_line[i + 1..];
156        let after_ws = after_hash.trim_start();
157        let ws_len = after_hash.len() - after_ws.len();
158        // A single `find` gives both "did a terminator turn up" and "where" — no need
159        // for a separate `contains` pass over the same text first (impl-critic-2 nit).
160        let terminator = after_ws.find(char::is_whitespace);
161        if terminator.is_none() && window == WindowCoverage::Truncated {
162            // The token has no observed end within the window, so its true text may
163            // continue past the edge — accepting it here risks silently recording a
164            // truncated-but-still-semver-shaped value (finding #1). Bail out rather than
165            // guess; the ref degrades to a bare, commentless pin instead of a wrong one.
166            return None;
167        }
168        let token_len = terminator.unwrap_or(after_ws.len());
169        let token = &after_ws[..token_len];
170        return if is_full_semver_shape(token) {
171            Some((token, i + 1 + ws_len + token_len))
172        } else {
173            None
174        };
175    }
176    None
177}

179/// Outcome of classifying a raw `uses:` scalar value's `owner/repo[...]` prefix.
180enum ParsedUses {
181    /// `./local` or `.\local` — a local composite action.
182    Path,
183    /// `docker://image:tag` — a Docker Hub / registry image reference.
184    Docker,
185    /// A bare `owner/repo` with no `@ref` at all — nothing to version.
186    NoAt { name: String },
187    /// `owner/repo@ref`, or a truncated `owner/repo/.github/workflows/x.yml@ref`.
188    Ref {
189        name: String,
190        is_reusable_workflow: bool,
191        /// Byte length of the value's full pre-`@` path (`owner/repo[/sub/path]`), NOT
192        /// `name.len()` — for a subdirectory action or reusable-workflow call, `name` is
193        /// truncated at the second `/` while the `@` sits after the untruncated path.
194        /// Using `name.len()` here would place `ref_text`'s range short by the truncated
195        /// subpath's length (critic S1 in the implementation review).
196        before_at_len: usize,
197        ref_text: String,
198    },
199    /// Does not look like a GitHub identifier at all — skipped entirely (FR-015).
200    Malformed,
201}
202
203/// Splits a raw `uses:` value into `owner/repo` (truncated at the second `/`) and its ref,
204/// classifying the source shape. Does not resolve the ref against the tags API — that is
205/// [`classify_ref`]'s job on the returned `ref_text`.
206fn classify_uses_value(value: &str) -> ParsedUses {
207    let value = value.trim();
208    if value.is_empty() {
209        return ParsedUses::Malformed;
210    }
211    if value.starts_with("./") || value.starts_with(".\\") {
212        return ParsedUses::Path;
213    }
214    if value.starts_with("docker://") {
215        return ParsedUses::Docker;
216    }
217
218    let (before_at, ref_text) = match value.split_once('@') {
219        Some((b, r)) => (b, Some(r)),
220        None => (value, None),
221    };
222
223    let mut segments = before_at.splitn(3, '/');
224    let (Some(owner), Some(repo)) = (segments.next(), segments.next()) else {
225        return ParsedUses::Malformed;
226    };
227    if owner.is_empty() || repo.is_empty() {
228        return ParsedUses::Malformed;
229    }
230    let name = format!("{owner}/{repo}");
231    if !crate::is_valid_github_identity(&name) {
232        return ParsedUses::Malformed;
233    }
234    let is_reusable_workflow = segments
235        .next()
236        .is_some_and(|rest| rest.starts_with(".github/workflows/"));
237
238    match ref_text {
239        None => ParsedUses::NoAt { name },
240        Some("") => ParsedUses::Malformed,
241        Some(r) => ParsedUses::Ref {
242            name,
243            is_reusable_workflow,
244            before_at_len: before_at.len(),
245            ref_text: r.to_string(),
246        },
247    }
248}

258/// Which special key (if any) a `Mapping` frame's `awaiting_key: false` state is
259/// currently waiting on the value for.
260#[derive(Clone, Copy, PartialEq, Eq)]
261enum PendingKey {
262    /// Not awaiting a value (`awaiting_key: true`), or the pending key is neither
263    /// `uses` nor `with`.
264    None,

266    With,

269struct Frame {
270    kind: FrameKind,
271    is_with_ancestor: bool,
272    awaiting_key: bool,
273    pending_key: PendingKey,

276/// One `uses:` scalar found by [`WorkflowReceiver`], not yet classified or range-mapped.
277struct UsesCandidate {
278    value: String,

287/// Collects every `uses:` value-scalar event, skipping any `uses` key that has a `with:`
288/// ancestor (a step input literally named `uses`) — covers `jobs.*.steps[].uses` and
289/// `jobs.<id>.uses` (reusable-workflow calls) with one rule, matching Renovate.
290///
291/// Also tracks [`Self::has_top_level_runs_key`] alongside `candidates`: both are derived
292/// from the same single streaming pass over the document's YAML events, so recomputing
293/// the `runs:` check separately (e.g. from the URI path instead) would mean a second,
294/// redundant walk of the same event stream for one boolean.
295struct WorkflowReceiver {
296    stack: Vec<Frame>,
297    candidates: Vec<UsesCandidate>,
298    /// Whether a `runs:` key was seen in the *document root* mapping (`stack.len() == 1`
299    /// at the time its key scalar fired) — issue #706 review finding (security, LOW):
300    /// `action.yml`/`action.yaml` is now routed by bare basename, matching any file with
301    /// that name anywhere in an opened workspace, not just real GitHub Action manifests.
302    /// GitHub requires every `action.yml`/`action.yaml` to declare a top-level `runs:`
303    /// key; [`parse_workflow_yaml`] uses this flag (via [`is_action_manifest_filename`])
304    /// to withhold every candidate for such a file when it's missing, cutting
305    /// false-positive registry fetches and diagnostics on a coincidentally-named,
306    /// unrelated file. Known limitation: a `runs:` key expressed only through a YAML
307    /// merge key (`<<: *anchor`) is not detected — this flag only recognizes a literal
308    /// `runs` scalar key, so such an action would be misclassified. Considered too
309    /// obscure to warrant merge-key resolution here.
310    has_top_level_runs_key: bool,
311}
312
313impl WorkflowReceiver {
314    fn new() -> Self {
315        Self {
316            stack: Vec::new(),
317            candidates: Vec::new(),
318            has_top_level_runs_key: false,
319        }
320    }
321
322    fn child_is_with_ancestor(&self) -> bool {
323        self.stack.last().is_some_and(|top| match top.kind {
324            FrameKind::Mapping => top.is_with_ancestor || top.pending_key == PendingKey::With,
325            FrameKind::Sequence => top.is_with_ancestor,
326        })
327    }
328
329    fn consume_pending_value(&mut self) {
330        if let Some(top) = self.stack.last_mut() {
331            top.awaiting_key = true;
332            top.pending_key = PendingKey::None;
333        }
334    }
335
336    fn push_container(&mut self, kind: FrameKind) {
337        let is_with_ancestor = self.child_is_with_ancestor();
338        self.consume_pending_value();
339        self.stack.push(Frame {
340            kind,
341            is_with_ancestor,
342            awaiting_key: true,
343            pending_key: PendingKey::None,
344        });
345    }
346}
347
348impl MarkedEventReceiver for WorkflowReceiver {
349    fn on_event(&mut self, event: Event, marker: Marker) {
350        match event {
351            Event::MappingStart(..) => self.push_container(FrameKind::Mapping),
352            Event::SequenceStart(..) => self.push_container(FrameKind::Sequence),
353            Event::MappingEnd | Event::SequenceEnd => {
354                self.stack.pop();
355                self.consume_pending_value();
356            }
357            Event::Scalar(value, style, _anchor, _tag) => {
358                let is_key = self
359                    .stack
360                    .last()
361                    .is_some_and(|top| matches!(top.kind, FrameKind::Mapping) && top.awaiting_key);
362                if is_key {
363                    if self.stack.len() == 1 && value == "runs" {
364                        self.has_top_level_runs_key = true;
365                    }
366                    if let Some(top) = self.stack.last_mut() {
367                        top.pending_key = if value == "uses" && !top.is_with_ancestor {
368                            PendingKey::Uses
369                        } else if value == "with" {
370                            PendingKey::With
371                        } else {
372                            PendingKey::None
373                        };
374                        top.awaiting_key = false;
375                    }
376                } else {
377                    let is_uses_value = self.stack.last().is_some_and(|top| {
378                        matches!(top.kind, FrameKind::Mapping)
379                            && top.pending_key == PendingKey::Uses
380                    });
381                    if is_uses_value {
382                        self.candidates.push(UsesCandidate {
383                            value,
384                            style,
385                            line: marker.line(),
386                            col: marker.col(),
387                        });
388                    }
389                    self.consume_pending_value();
390                }
391            }
392            // A `uses: *anchor` alias value must still clear the pending `uses`/`with`
393            // key slot, or the next mapping key/value pair desyncs (the following key
394            // gets consumed as if it were this `uses`'s value) — critic M5. GitHub
395            // itself does not support YAML anchors/aliases in workflow files, so this
396            // is defense-in-depth rather than a reachable real-world case.
397            Event::Alias(_) => self.consume_pending_value(),
398            Event::Nothing
399            | Event::StreamStart
400            | Event::StreamEnd
401            | Event::DocumentStart
402            | Event::DocumentEnd => {}
403        }
404    }
405}

407/// Builds a [`GithubActionsDependency`] for one `uses:` candidate, or `None` if its
408/// `owner/repo` prefix does not look like a GitHub identifier (logged and skipped, FR-015).
409// `ref_start`/`ref_end` build on `span_start`, which is char-boundary-aligned in `content` via
410// `marker_byte_offset` + `locate_value_span` and then re-anchored to the trimmed value
411// (see the trim re-anchoring comment below) — plus `before_at_len`/`ref_text.len()`, both
412// whole-substring byte counts, so the arithmetic never lands mid-character. `token_end` is
413// relative to `content[ref_end..]`, windowed to at most `REST_OF_LINE_WINDOW_BYTES` past
414// `ref_end` and to the line's own end (resolved via `line_table.line_start` in O(1)), rather
415// than an unbounded `find('\n')` scan (issue #885).
416#[allow(clippy::string_slice)]
417fn build_dependency(
418    content: &str,
419    line_table: &LineOffsetTable,
420    candidate: UsesCandidate,
421) -> Option<GithubActionsDependency> {
422    // Whether the *whole* `uses:` value scalar was written unquoted. For a quoted scalar,
423    // any `Range` computed below sits inside the quotes — a SHA-pin code action (issue
424    // #473) must not write `{sha} # {tag}` there, since the `#` would land inside the
425    // string rather than starting a YAML comment (spec 031 FR-010). Read once here and
426    // carried on every constructed dependency, mirroring the existing single-purpose
427    // `TScalarStyle::Plain` gate below for the SHA-with-comment case.
428    let is_plain_scalar = candidate.style == TScalarStyle::Plain;
429
430    let value_start = marker_byte_offset(content, line_table, candidate.line, candidate.col);
431    let (raw_start, raw_end) = locate_value_span(content, value_start, &candidate.value)?;
432
433    // `classify_uses_value` (and every offset computed below) works over the
434    // *trimmed* value, but the span located above is the raw, untrimmed scalar
435    // text. For a quoted `uses:` value with leading/trailing whitespace (e.g.
436    // `" actions/checkout@v4"`), anchoring the downstream `name.len()`/
437    // `before_at_len`-relative arithmetic to the untrimmed start desyncs every
438    // computed offset by the trimmed byte count: on ordinary ASCII input this
439    // silently points `version_range` at the wrong text (an accepted "update
440    // version" code action then overwrites the wrong span), and on multi-byte
441    // leading whitespace (e.g. an ideographic space, U+3000) it can split a UTF-8
442    // sequence and panic on a raw `content[..]` slice downstream (security S-1).
443    // Re-anchoring `span_start`/`span_end` to the trimmed text here — both still
444    // guaranteed char-boundary-aligned in `content`, since `str::trim_start`/
445    // `trim_end` only ever cut at `candidate.value`'s own char boundaries, and
446    // that value is byte-identical to `content[raw_start..raw_end]` by
447    // `locate_value_span`'s own contract — means every reference to them
448    // downstream is already correct, with no further per-call adjustment needed.
449    let leading_ws = candidate.value.len() - candidate.value.trim_start().len();
450    let trailing_ws = candidate.value.len() - candidate.value.trim_end().len();
451    let span_start = raw_start + leading_ws;
452    let span_end = raw_end.saturating_sub(trailing_ws);
453    let trimmed_value = candidate.value.trim().to_string();
454
455    let make_range = |start: usize, end: usize| -> Range {
456        Range::new(
457            line_table.byte_offset_to_position(content, start),
458            line_table.byte_offset_to_position(content, end),
459        )
460    };
461
462    match classify_uses_value(&candidate.value) {
463        ParsedUses::Path => Some(GithubActionsDependency {
464            name: trimmed_value.clone().into(),
465            name_range: make_range(span_start, span_end),
466            version_req: None,
467            version_range: None,
468            version_literal: None,
469            pin: None,
470            source: DependencySource::Path {
471                path: trimmed_value,
472            },
473            is_plain_scalar,
474            is_last_on_line: true,
475        }),
476        ParsedUses::Docker => Some(GithubActionsDependency {
477            name: trimmed_value.clone().into(),
478            name_range: make_range(span_start, span_end),
479            version_req: None,
480            version_range: None,
481            version_literal: None,
482            pin: None,
483            source: DependencySource::Url { url: trimmed_value },
484            is_plain_scalar,
485            is_last_on_line: true,
486        }),
487        ParsedUses::NoAt { name } => {
488            let name_end = span_start + name.len();
489            Some(GithubActionsDependency {
490                name: name.into(),
491                name_range: make_range(span_start, name_end),
492                version_req: None,
493                version_range: None,
494                version_literal: None,
495                pin: None,
496                source: DependencySource::Registry,
497                is_plain_scalar,
498                is_last_on_line: true,
499            })
500        }
501        ParsedUses::Ref {
502            name,
503            is_reusable_workflow,
504            before_at_len,
505            ref_text,
506        } => {
507            let name_end = span_start + name.len();
508            // Not `name_end + 1`: `name` is truncated at the second `/` for a
509            // subdirectory action or reusable-workflow call, but the `@` sits after the
510            // full pre-`@` path (`before_at_len`) — using `name_end` would place every
511            // ref offset short by the truncated subpath's length (critic S1).
512            let ref_start = span_start + before_at_len + 1; // skip the '@'
513            let ref_end = ref_start + ref_text.len();
514            let name_range = make_range(span_start, name_end);
515
516            if is_reusable_workflow {
517                return Some(GithubActionsDependency {
518                    name: name.clone().into(),
519                    name_range,
520                    version_req: None,
521                    version_range: None,
522                    version_literal: None,
523                    pin: None,
524                    source: DependencySource::Url {
525                        url: format!("https://github.com/{name}"),
526                    },
527                    is_plain_scalar,
528                    is_last_on_line: true,
529                });
530            }
531
532            // O(1) real line-end lookup via `line_table` instead of an unbounded
533            // `find('\n')` scan (issue #885): the latter scanned to end-of-document
534            // once per ref-pinned dependency, an O(N x remaining-document-length)
535            // cost on a single-line manifest with N such deps. Mirrors
536            // `marker_byte_offset`'s own use of `LineOffsetTable::line_start` — that
537            // returns the byte offset right after this line's own '\n' (0-indexed
538            // line `candidate.line`, so passing the 1-indexed `candidate.line` here
539            // lands on the *next* line's start), or `content.len()` if this is the
540            // last line with no trailing newline. `line_end` is always a `content`
541            // char boundary (built from a `char_indices()` walk), and stepping back
542            // one byte off it is too when that byte is the single-byte '\n' itself,
543            // so no boundary clamp is needed for it specifically.
544            let line_end = line_table
545                .line_start(candidate.line)
546                .unwrap_or(content.len());
547            let line_end = match line_end.checked_sub(1) {
548                Some(i) if content.as_bytes().get(i) == Some(&b'\n') => i,
549                _ => line_end,
550            };
551            // Even a correctly-located line can itself be enormous — a
552            // single-physical-line manifest with many ref-pinned dependencies and
553            // no real newline anywhere is exactly #885's threat model, and neither
554            // `ref_is_last_token_on_line` nor `extract_comment_tag` needs more than
555            // a short window after the ref. Cap the window at
556            // `REST_OF_LINE_WINDOW_BYTES` past `ref_end`; `floor_char_boundary`
557            // clamps it back to a valid boundary since (unlike `line_end`) this
558            // bound isn't guaranteed to land on one. `line_end < ref_end` is
559            // defense-in-depth for a `line_table`/`ref_end` mismatch that shouldn't
560            // occur in practice — logged distinctly below (code-review finding #8)
561            // since it's a desync bug, not routine truncation, and without this
562            // disjunct such a mismatch would silently look untruncated instead of
563            // failing safe.
564            let line_end_desynced = line_end < ref_end;
565            if line_end_desynced {
566                tracing::debug!(
567                    ref_end,
568                    line_end,
569                    candidate_line = candidate.line,
570                    "line_table line_end is before ref_end; this should not happen \
571                     in practice — treating the rest-of-line window as truncated"
572                );
573            }
574            let capped_end = ref_end
575                .saturating_add(REST_OF_LINE_WINDOW_BYTES)
576                .min(line_end);
577            let window_truncated = line_end_desynced || capped_end < line_end;
578            let window = if window_truncated {
579                WindowCoverage::Truncated
580            } else {
581                WindowCoverage::FullLine
582            };
583            let capped_end = content.floor_char_boundary(capped_end);
584            let rest_of_line = &content[ref_end..capped_end.max(ref_end)];
585            // Security audit finding (issue #633): computed for every ref-pinned form,
586            // not just the SHA-with-comment case below, since the mutable-tag SHA-pin
587            // edit (`sha_pin_text_edit_for`) needs it for `PinStyle::Tag` too — a flow-
588            // style step (`{uses: actions/checkout@v4, with: {...}}`) has real YAML
589            // content after the ref that a trailing `# <tag>` comment would swallow.
590            // `ref_is_last_token_on_line` gives a definitive answer whenever it finds
591            // a `#` comment or real content within the (possibly truncated) window —
592            // `window` only matters as the fallback when the window is all
593            // whitespace with nothing conclusive in it, where we cannot safely assume
594            // "nothing unsafe follows" (issue #885 rework, impl-critic S1: a naive
595            // bounded window without this fallback flipped `is_last_on_line` from
596            // false to true once enough padding separated the ref from a real
597            // flow-style continuation, reopening the #633 corruption).
598            let is_last_on_line = ref_is_last_token_on_line(rest_of_line, window);
599
600            if is_full_sha(&ref_text) {
601                // `extract_comment_tag` takes the first whitespace-preceded `#` anywhere
602                // in `rest_of_line`, with no notion of whether that `#` is genuinely this
603                // ref's own trailing comment or belongs to an unrelated later token on the
604                // same flow-style line (issue #898). `is_last_on_line` already answers
605                // exactly that question (see the #633 comment above): reuse it as a gate
606                // so a flow-style continuation (`, with: {...}}`) is never misread as this
607                // ref's comment, which previously computed an over-wide `version_range`
608                // spanning real YAML content past the ref.
609                let comment = (is_plain_scalar && is_last_on_line)
610                    .then(|| extract_comment_tag(rest_of_line, window))
611                    .flatten();
612
613                return Some(match comment {
614                    Some((tag, token_end)) => GithubActionsDependency {
615                        name: name.into(),
616                        name_range,
617                        version_req: Some(tag.into()),
618                        version_range: Some(make_range(ref_start, ref_end + token_end)),
619                        version_literal: Some(content[ref_start..ref_end + token_end].to_string()),
620                        pin: Some(PinStyle::Sha {
621                            comment_tag: Some(tag.to_string()),
622                        }),
623                        source: DependencySource::Registry,
624                        is_plain_scalar,
625                        is_last_on_line,
626                    },
627                    None => GithubActionsDependency {
628                        name: name.into(),
629                        name_range,
630                        version_req: Some(ref_text.into()),
631                        version_range: Some(make_range(ref_start, ref_end)),
632                        version_literal: None,
633                        pin: Some(PinStyle::Sha { comment_tag: None }),
634                        source: DependencySource::Registry,
635                        is_plain_scalar,
636                        is_last_on_line,
637                    },
638                });
639            }
640
641            let pin = if is_tag_shaped(&ref_text) {
642                PinStyle::Tag
643            } else {
644                PinStyle::Branch
645            };
646            Some(GithubActionsDependency {
647                name: name.into(),
648                name_range,
649                version_req: Some(ref_text.into()),
650                version_range: Some(make_range(ref_start, ref_end)),
651                version_literal: None,
652                pin: Some(pin),
653                source: DependencySource::Registry,
654                is_plain_scalar,
655                is_last_on_line,
656            })
657        }
658        ParsedUses::Malformed => {
659            // Logs only the value's length, not the raw attacker-controlled text
660            // (security S-5) — matches every other rejection site in the workspace,
661            // e.g. `deps_swift::registry::validate_owner_repo`.
662            warn_rejected_value(
663                "classify_uses_value",
664                "workflow uses: value",
665                &candidate.value,
666            );
667            None
668        }
669    }

672/// Parses a `.github/workflows/*.yml`/`*.yaml` file and returns every `uses:` dependency
673/// found, with LSP position tracking.
674///
675/// Gated first (as `deps-dart`'s pubspec.yaml parser) by
676/// [`deps_core::check_yaml_nesting_depth`]/[`deps_core::check_yaml_expansion`], which return
677/// a real [`DepsError::ParseError`]. A downstream YAML syntax error, by contrast, degrades to
678/// an **empty** [`GithubActionsParseResult`] (logged at `debug`) rather than propagating —
679/// workflows are numerous per repository, and one malformed file should not disable hover/
680/// completion for every other open workflow.
681///
682/// # Errors
683///
684/// Returns [`DepsError::ParseError`] only when `content` exceeds the shared YAML
685/// nesting-depth or expansion-size gate.
686///
687/// # Examples
688///
689/// ```
690/// use deps_core::Dependency;
691/// use deps_github_actions::parse_workflow_yaml;
692///
693/// let content = "steps:\n  - uses: actions/checkout@v4\n";
694/// let uri = deps_core::test_util::test_uri("/repo/.github/workflows/ci.yml");
695/// let result = parse_workflow_yaml(content, &uri).unwrap();
696///
697/// assert_eq!(result.dependencies.len(), 1);
698/// assert_eq!(result.dependencies[0].name(), "actions/checkout");
699/// ```
700pub fn parse_workflow_yaml(content: &str, uri: &Uri) -> Result<GithubActionsParseResult> {
701    if let Err(depth) =
702        deps_core::check_yaml_nesting_depth(content, deps_core::MAX_YAML_NESTING_DEPTH)
703    {
704        return Err(DepsError::ParseError {
705            file_type: "workflow.yml".into(),
706            source: Box::new(std::io::Error::other(format!(
707                "YAML nesting depth {depth} exceeds maximum of {}",
708                deps_core::MAX_YAML_NESTING_DEPTH
709            ))),
710        });
711    }
712    if let Err(bytes) = deps_core::check_yaml_expansion(content, deps_core::MAX_YAML_EXPANDED_BYTES)
713    {
714        return Err(DepsError::ParseError {
715            file_type: "workflow.yml".into(),
716            source: Box::new(std::io::Error::other(format!(
717                "YAML expansion {bytes} bytes exceeds maximum of {} bytes",
718                deps_core::MAX_YAML_EXPANDED_BYTES
719            ))),
720        });
721    }
722
723    let mut receiver = WorkflowReceiver::new();
724    let mut parser = Parser::new_from_str(content);
725    if let Err(e) = parser.load(&mut receiver, false) {
726        tracing::debug!(error = %e, "failed to parse workflow YAML, treating as empty");
727        return Ok(GithubActionsParseResult {
728            dependencies: Vec::new(),
729            uri: uri.clone(),
730            dependency_truncation: None,
731        });
732    }
733
734    // Issue #706 review finding (security, LOW): `action.yml`/`action.yaml` is routed by
735    // bare basename (`Ecosystem::manifest_filenames`), which matches anywhere in an
736    // opened workspace — not just real GitHub Action manifests. Withhold every candidate
737    // for such a file unless it actually declares GitHub's own required top-level
738    // `runs:` key, so a coincidentally-named, unrelated `action.yml` degrades to zero
739    // dependencies instead of issuing live registry fetches and diagnostics.
740    if is_action_manifest_filename(uri) && !receiver.has_top_level_runs_key {
741        tracing::debug!(
742            "action.yml/action.yaml with no top-level `runs:` key, treating as not a \
743             GitHub Action manifest"
744        );
745        return Ok(GithubActionsParseResult {
746            dependencies: Vec::new(),
747            uri: uri.clone(),
748            dependency_truncation: None,
749        });
750    }
751
752    let line_table = LineOffsetTable::new(content);
753    // #796: checked before `build_dependency` (the expensive step — SHA/tag resolution
754    // setup, range computation) rather than after, so a `uses:` step beyond the ceiling
755    // never reaches it.
756    let mut budget = deps_core::DependencyBudget::new(deps_core::MAX_DEPENDENCIES_PER_DOCUMENT);
757    let dependencies = receiver
758        .candidates
759        .into_iter()
760        .filter(|_| budget.allow())
761        .filter_map(|candidate| build_dependency(content, &line_table, candidate))
762        .collect();
763
764    Ok(GithubActionsParseResult {
765        dependencies,
766        uri: uri.clone(),
767        dependency_truncation: budget.truncation(),
768    })
769}

771/// Whether `uri`'s basename is exactly `action.yml` or `action.yaml` — the same
772/// case-sensitive exact-name match [`crate::ecosystem::GithubActionsEcosystem::manifest_filenames`]
773/// registers with [`deps_core::EcosystemRegistry`], recomputed here since routing itself
774/// carries no signal into [`parse_workflow_yaml`] about *which* rule matched.
775///
776/// Deliberately does not special-case `.github/workflows/`: GitHub's own naming
777/// convention makes a *workflow* actually named `action.yml` vanishingly unlikely (that
778/// name specifically signals "this is an action manifest", not a workflow), so per the
779/// project's MVP convention this stays a plain basename check rather than adding a
780/// directory carve-out (and its own tests) for a near-hypothetical file. Should such a
781/// workflow exist, [`parse_workflow_yaml`]'s "requires a top-level `runs:` key" guard
782/// below would misclassify it and drop its `uses:` steps until renamed.
783fn is_action_manifest_filename(uri: &Uri) -> bool {
784    let path = uri.path().as_str();
785    let filename = path.rsplit('/').next().unwrap_or(path);
786    filename == "action.yml" || filename == "action.yaml"
787}
