1//! GitHub Actions ecosystem support for deps-lsp.
2//!
3//! Provides LSP features for `.github/workflows/*.yml`/`*.yaml` files:
4//! - Version autocomplete and hover for `uses: owner/repo@ref` steps
5//! - Diagnostics and code actions for outdated tag pins and SHA-with-comment pins
6//! - GitHub tags API for version discovery, with per-repository commit SHA resolution
7//!
8//! # Pin contract
9//!
10//! | `uses:` form | `version_range` spans | `version_requirement()` | `version_literal()` |
11//! |---|---|---|---|
12//! | `actions/checkout@v4` | `v4` | `v4` | `None` |
13//! | `…@v4.2.0` / `…@4.2.0` | the tag | same | `None` |
14//! | `…@<40hex> # v4.2.0` | `<40hex> # v4.2.0` | `v4.2.0` (from the comment) | the raw span |
15//! | `…@<40hex>` (no comment) | `<40hex>` | `<40hex>` | `None` |
16//! | `…@main` | `main` | `main` | `None` |
17//! | `./local`, `docker://x:1`, a reusable-workflow call | `None` | `None` | `None` |
18//!
19//! Reusable-workflow calls (`owner/repo/.github/workflows/x.yml@ref`) are recognized and
20//! their `owner/repo` truncated for display, but treated as non-resolvable — same shape as
21//! `./local`/`docker://` — because the referenced workflow's version and the host repo's
22//! release tags are not reliably the same thing (see `parser` module docs).

38/// Stable [`tower_lsp_server::ls_types::Diagnostic::code`] for the mutable-ref-pin
39/// diagnostic (issue #473).
40///
41/// Flags a `uses:` step pinned to a tag rather than a full commit SHA, a supply-chain
42/// hardening recommendation distinct from the outdated-version check.
43///
44/// Local to this crate rather than a shared `deps-core` diagnostic kind — mirrors the
45/// shape of `deps_core::UNSATISFIABLE_DIAGNOSTIC_CODE`/`deps_core::DEPRECATED_DIAGNOSTIC_CODE`,
46/// but no second ecosystem needs the same "mutable ref" concept yet (spec 031's resolved
47/// Open Questions), so generalizing into `deps-core` would be premature.
48pub const MUTABLE_REF_PIN_DIAGNOSTIC_CODE: &str = "mutable-ref-pin";

50/// `workspace/executeCommand` id for the "Pin N actions to commit SHA" bulk code lens
51/// (issue #633).
52///
53/// Bulk counterpart of the per-step "Pin to commit SHA" quickfix (issue #473): rewrites
54/// every `PinStyle::Tag` step in a workflow that has a resolvable `TagIndex` entry in one

56/// "Update N outdated dependencies" lens.

59/// Whether `name` matches the `owner/repo` GitHub identifier shape this crate accepts:
60/// `[a-zA-Z0-9._-]+/[a-zA-Z0-9._-]+`, with neither segment being exactly `.`/`..` (see
61/// [`deps_core::is_dot_segment`]).
62///
63/// Shared by `registry::validate_owner_repo` (a credential-bearing fetch-URL gate) and
64/// `formatter::GithubActionsFormatter::package_url` (a display-URL gate). Delegates to
65/// [`deps_core::github::is_valid_github_identity`], shared with `deps-swift` so both
66/// GitHub-tags-backed crates cannot drift apart on what counts as a valid identity (#472).
67///
68/// # Examples
69///
70/// ```
71/// use deps_github_actions::is_valid_github_identity;
72///
73/// assert!(is_valid_github_identity("actions/checkout"));
74/// assert!(!is_valid_github_identity("not-a-valid-identifier"));
75/// assert!(!is_valid_github_identity("owner/.."));
76/// ```
77pub use deps_core::github::is_valid_github_identity;
