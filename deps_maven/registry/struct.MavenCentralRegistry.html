pub async fn get_versions_typed_with( &self, name: &str, freshness_enabled: bool, ) -> Result<Vec<MavenVersion>>

Same as Self::get_versions_typed, but attaches MavenVersion::published_at from the repo1.maven.org directory listing when freshness_enabled and the artifact resolved through Maven Central.

The listing fetch is gated on the winning base being Maven Central specifically — not merely present — because Google Maven’s listing always 404s (no negative caching in HttpCache, so an unconditional fetch would retry forever) and the Gradle Plugin Portal’s listing has no date column (a wasted fetch+parse on every call). Both degrade to zero extra requests here rather than one doomed one.

pub async fn search_typed( &self, query: &str, limit: usize, ) -> Result<Vec<ArtifactInfo>>

Searches Maven Central for artifacts matching query.

Retries against solrsearch via search_with_retry, falling back to a stale cached result (if any) on failure, to work around its silent-timeout unreliability (#274) without exceeding the caller’s own completion deadline. See SEARCH_ATTEMPT_TIMEOUTS and search_with_retry for the retry/fallback policy.

A query that failed live within the last RECENT_FAILURE_TTL short-circuits to the same error with no network attempt at all (#282 gap 1) — this is what keeps a completion request’s own fallback search (deps-lsp’s completion.rs) from doubling live request volume against an endpoint that is already fast-failing for this query, since a fast failure (unlike a hang) returns well inside the caller’s own deadline and so does not get skipped by that deadline alone.

The request always asks solrsearch for SEARCH_CACHE_ROWS rows regardless of limit (#282 gap 2), so that calls with different limits for the same query share one HttpCache entry — limit only trims the parsed result afterward via parse_search_response.

§Errors

Returns the last error (an HTTP/network error, or a synthesized timeout error) if every attempt fails and no cached result is available to fall back to.
